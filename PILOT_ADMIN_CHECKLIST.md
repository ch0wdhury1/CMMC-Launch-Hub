# CMMC Launch Hub Pilot Admin Checklist

Date: 2026-06-03  
Hosted URL: https://cmmc-launch-hub.web.app

## Before Pilot Onboarding

- [ ] Confirm the organization is approved and active.
- [ ] Confirm the organization name is correct.
- [ ] Confirm the primary OrgAdmin account can sign in.
- [ ] Confirm the OrgAdmin sees Admin and Profile controls.
- [ ] Confirm the OrgAdmin does not see Super Admin controls.
- [ ] Confirm the company profile displays the correct organization identity.
- [ ] Confirm intended pilot roles are documented before invitations are sent.

## SuperAdmin Checklist

- [ ] Review Pending Registrations.
- [ ] Review active, inactive, and archived organization tabs.
- [ ] Open Activity Center and confirm all expected pilot organizations are available in the organization filter.
- [ ] Use date, organization, and action filters to review recent pilot activity.
- [ ] Export CSV when an audit extract is needed for support or incident review.
- [ ] Confirm the request identity before approval or status changes.
- [ ] Confirm the user and organization belong together.
- [ ] Confirm inactive or disabled access is intentional.
- [ ] Record organization-level actions in the pilot support log.
- [ ] Escalate any cross-organization visibility concern immediately.

## OrgAdmin User Management Checklist

- [ ] Open Profile and review Users for the organization.
- [ ] Confirm no users from another organization are visible.
- [ ] Open Activity Center and confirm only the signed-in organization activity is visible.
- [ ] Use date and action filters to review organization activity.
- [ ] Invite only approved pilot participants.
- [ ] Assign the least-privileged appropriate role.
- [ ] Confirm the invitation email and role before submission.
- [ ] Review pending invitations for stale or incorrect entries.
- [ ] Verify inactive users are blocked when access should be removed.

## OrgAdmin Profile Checklist

- [ ] Review Company Information.
- [ ] Confirm the legal or display name is correct.
- [ ] Confirm primary contact information is current.
- [ ] Use Edit My Info for supported personal identity updates.
- [ ] Reload after personal information changes and confirm persistence.
- [ ] Do not attempt to self-edit email, role, status, active state, organization ID, or SuperAdmin status.

## Assessment Checklist

- [ ] Open Command Dashboard.
- [ ] Select the correct CMMC level, domain, and practice.
- [ ] Confirm the intended assessment objective is visible.
- [ ] Review objective status, notes, and assignment.
- [ ] Use the header Save action after changes.
- [ ] Wait for the Saved state before leaving the page.
- [ ] Reload and confirm critical changes persist.

## Evidence Checklist

- [ ] Confirm the user role is permitted to manage evidence.
- [ ] Confirm Viewer accounts do not see any upload or archive controls.
- [ ] Upload evidence to the intended practice or objective.
- [ ] Confirm `Storage: uploaded`.
- [ ] Confirm the evidence record appears.
- [ ] Review OCR status and OCR Preview.
- [ ] Test View and Download when needed.
- [ ] Archive only when the record should leave the active evidence view.
- [ ] Use Show Archived Evidence to confirm archived records remain available.

## Reporting Checklist

- [ ] Expand COMPLIANCE REPORTING.
- [ ] Generate the Executive Readiness Report.
- [ ] Confirm the signed-in organization name appears.
- [ ] Confirm no other organization identity appears.
- [ ] Generate the POA&M Report or review its valid empty state.
- [ ] Confirm the signed-in organization name appears in the POA&M report.
- [ ] Export PDF only when the role permits it.

## Incident Checklist

- [ ] Record the organization, user, role, date, time, and page.
- [ ] Record the exact action and expected result.
- [ ] Capture screenshots and displayed messages.
- [ ] Note whether the issue persists after reload.
- [ ] Note whether another role or organization is affected.
- [ ] Treat cross-organization visibility or unauthorized controls as critical.
- [ ] Do not change credentials, security rules, or data structures as an ad hoc fix.
- [ ] Escalate according to the Pilot Support Playbook.

## End-of-Week Pilot Review

- [ ] Review open support issues.
- [ ] Review OCR failures and recurrence.
- [ ] Review invitations and inactive users.
- [ ] Review evidence workflow issues.
- [ ] Review reporting identity and export issues.
- [ ] Confirm no security or isolation concerns remain open.
- [ ] Record decisions, owners, and follow-up dates.
