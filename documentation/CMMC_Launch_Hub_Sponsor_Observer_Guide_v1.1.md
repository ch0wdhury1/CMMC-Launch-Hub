# 1. Program Overview

## Purpose

CMMC Launch Hub gives authorized sponsors a read-only oversight workspace for monitoring readiness progress across participating organizations.

## Commercial vs Sponsored Organizations

| Type | Observer relevance |
| --- | --- |
| Commercial organization | Usually not visible to Program Observers unless included in sponsor/pilot visibility by platform configuration. |
| Sponsored program organization | Assigned to a program and visible to authorized Program Observers for that program. |

## Program Lifecycle

1. Program is created by platform administrator.
2. Organizations register through the sponsored path or are assigned to the program.
3. Sponsor/Program Observers are assigned.
4. Participants work on profile, assessment, evidence, reports, and marketplace engagement.
5. Observers monitor sanitized readiness progress.

## Observer Responsibilities

Observers typically:

- Monitor participant readiness progress.
- Identify organizations that may need support.
- Review completion and evidence count trends.
- Review generated report indicators.
- Review vendor engagement summaries.
- Coordinate with organizations outside the platform when deeper detail is needed.

> **WARNING**  
> Observer dashboards are not a substitute for a formal assessment or customer authorization to inspect sensitive materials.

------------------------------------------------

[SCREENSHOT:

------------------------------------------------

## Purpose

The Pilot Dashboard provides a sponsor-safe overview of participant readiness and activity.

## KPIs

Dashboard KPIs may include:

- Active organizations.
- Total pilot users.
- Average completion percentage.
- Average SPRS score.
- Evidence uploaded count.
- Open POA&M items.
- Reports generated.
- Feedback items.

## Charts and Tables

Dashboard charts and tables may show readiness trends, activity, organization summaries, and support indicators.

## Recent Activity

Recent Activity is metadata-only. Evidence events are summarized without exposing files or filenames.

## Refresh Workflow

1. Open Dashboard.
2. Review KPI changes.
3. Review participant list or Program Analytics for detail.
4. Follow up with organizations outside the platform if deeper information is required.

> **TIP**  
> Use dashboard metrics to identify support priorities. Do not assume low progress means noncompliance; it may mean the organization has not entered data yet.

## Purpose

Participant Detail gives a sponsor-safe view of one organization's readiness progress.

## Cards and Sections

| Section | What it shows |

| Organization information | Company name, location, email/user identifier, tier, users count. |
| Readiness summary | Practices completed, remaining, readiness percentage. |

## SPRS

SPRS score may be displayed where available as a readiness indicator.

POA&M generated indicates whether a POA&M report/workflow has been generated. It does not expose POA&M contents.

Engagement summaries may include:

- Vendor name.
- Category.
- Engagement type.
- Status.
- Start/end date.
- Participant summary.

No pricing, contracts, files, private notes, or private messages are shown.

## Completion Distribution

Shows participant readiness grouped by completion range.

## Vendor Analytics

Vendor analytics include top marketplace vendors used, organizations using vendors, and active engagement counts.

## Reports Generated

Report metrics show counts and flags only. Report contents are not available to observers.

# 8. Security Boundaries

This chapter is intentionally explicit. Sponsor and Program Observer access is designed to support oversight without exposing participant-sensitive materials.

## Observers Cannot See

Observers cannot see:

- Raw evidence files.
- Uploaded documents.
- Evidence filenames.
- Assessment notes.
- Private notes.
- Remediation details.
- AI conversations.
- SSP contents.
- POA&M contents.
- Full report contents.
- Organization mutation controls.
- Approval/rejection controls.
- User management controls.

## Observers Can See

Observers may see:

- Organization names in authorized scope.
- Readiness summaries.
- Domain readiness summaries.
- Evidence counts.
- Report generated flags/counts.
- SPRS score where available.
- Open POA&M count.
- Metadata-only recent activity.
- Sanitized marketplace engagement summaries.

> **BEST PRACTICE**  
> If a sponsor needs deeper details, request them directly from the organization through an agreed support or advisory process. Do not attempt to use observer access as a document review channel.

## Program-Scoped Security

Program Observers assigned to specific programs see only organizations assigned to those programs. Organizations with no matching program assignment are excluded.

# 9. Best Practices

## Monitoring

- Review dashboard weekly.
- Focus on low-completion organizations.
- Check inactive or no-activity participants.
- Review evidence counts and report flags.

## Weekly Reviews

Suggested weekly sponsor review:

1. Open Dashboard.
2. Review active organization count.
3. Open Program Analytics.
4. Review low-progress organizations.
5. Review vendor engagement summary.
6. Document follow-up items outside the platform.

## Working With Organizations

- Use metrics as conversation starters.
- Avoid interpreting missing data as failure without confirmation.
- Encourage organizations to complete profile and evidence workflows.
- Use POA&M and Executive Report flags as readiness milestones.

## Supporting Readiness

Sponsors can support readiness by:

- Encouraging consistent weekly updates.
- Providing onboarding help.
- Connecting participants with appropriate resources.
- Monitoring program-level trends.

# 10. Troubleshooting, FAQ, Glossary, and Appendices

## Troubleshooting

| Issue | Possible cause | Suggested action |
| --- | --- | --- |
| Cannot log in | Password, inactive account, or incomplete setup. | Reset password or contact platform support. |
| No participants visible | No program assignment or no assigned organizations. | Contact platform administrator. |
| Expected organization missing | Org may not be assigned to observer program. | Ask SuperAdmin to verify program assignment. |
| Analytics unavailable | Data service issue or access mismatch. | Retry and escalate to support. |
| Marketplace data missing | Vendor inactive or filters too narrow. | Clear filters and retry. |

## FAQ

1. **Can I edit participant data?**  
   No. Observer access is read-only.

2. **Can I download evidence?**  
   No. Evidence files are not available to observers.

3. **Can I see report contents?**  
   No. You can see generated flags/counts only.

4. **Can I see organizations outside my program?**  
   Program Observers cannot see organizations outside assigned program scope.

5. **Can I approve registrations?**  
   No. Only SuperAdmins handle approvals.

6. **Can I moderate marketplace reviews?**  
   No, unless you also have SuperAdmin access.

7. **What does Active Vendor Engagements mean?**  
   It counts vendor engagements marked active.

8. **What if dashboard data appears stale?**  
   Ask the participant to update their assessment/evidence data or contact support.
